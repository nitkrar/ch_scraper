# Phase 1.5: Test isolation + path helpers + staging directory restructure

**Date:** 2026-05-27
**Status:** Design v2 (after adversarial review)
**Companion:** [`2026-05-27-phase-1.5-implementation.md`](./2026-05-27-phase-1.5-implementation.md) — verifiable execution checklist
**Predecessor:** Phase 1 refactor landed at commit `df7d19a` on `trunk`. Pre-Phase-1.5 bookmark: tag will be added in implementation Step 0.

## Problem

After the Phase 1 subpackage refactor, three related issues remain:

1. **Test isolation is broken for 3 financials tests.** They read from `data/staging/filings/07545840/`, a per-company prod-data path. On any fresh checkout, those tests error before any real assertion runs. The parser test also asserts exact filing dates from the `07545840` sample, so it needs that exact company fixture — not an arbitrary substitute. (4th failure: a flaky 256MB RSS-bound staging test — DELETE candidate; the signal isn't reliable enough to act on.)
2. **~50 inline path constructions duplicate the same patterns** across tests and `ch_bulk/` source. Examples:
   - `Path(data_dir) / "staging"` appears in `core/logging.py`, `db/staging.py`, `web/classifier.py`, `companies_house/financials_enricher.py`, plus 6 test files.
   - `Path(data_dir) / "staging" / "filings" / company_number` appears in `financials_enricher.py:891,1418` and 12+ test sites.
   - `Path(data_dir) / "logs"` appears in `core/logging.py:24,62`.
   This is the same DRY problem we fixed for `DEFAULT_DB_PATH` — should extend `core/paths.py` with the missing helpers.
3. **`data/staging/` tree was ad-hoc.** Mixed-case directories (`Scrapes/`, `Validation/`), spaces in names (`Financial filings/`), no separation between active runtime batches, fetched raw artifacts, derived outputs, and historical archives. User has already renamed `data/staging/` → `data/old_staging/` to clear the slate.

These three issues compound: fixing the test isolation requires touching staging paths; touching staging paths requires the helpers; both require deciding what the new staging layout looks like.

Current local baseline on this checkout: `81` tests run, `1` fail, `9` errors, with `test_load_cqc_staging_large_batch_keeps_memory_bounded` intermittently adding a second failure. Phase 1.5 scope fixes the 3 financials fixture-path failures and deletes the flaky RSS test. The 7 Playwright/browser-launch classifier errors are pre-existing and out of scope for this phase.

## Non-goals

- **No production code logic changes.** Only path-resolution helpers and call-site rewrites that route through them.
- **No test additions.** Inventory tests, fix what's broken, delete what doesn't earn its keep — but don't write new ones in this phase.
- **No `data/old_staging/` deletion.** It stays as-is for reference; future cleanup decides.
- **No Playwright / browser-launch environment fix.** The classifier tests that currently fail because headless Chromium cannot launch on this machine are follow-up work, not Phase 1.5.
- **No git-tracking of historical bulk data.** The new `data/staging/` tree stays gitignored, and the large `data/old_staging/` payload stays ignored. Small tracked artifacts are limited to `tests/fixtures/`, the existing `data/reference/` files, and one `data/old_staging/README.md` pointer.
- **No new test framework.** Stay on stdlib `unittest`.

## Approach

Three workstreams land in one commit:

### Workstream A: Test isolation

- Create `tests/fixtures/` (tracked in git) for small, curated, test-owned data.
- Copy the exact historical file `data/old_staging/Scrapes/Financial filings/ixbrl/07545840.ixbrl` into `tests/fixtures/financials/ixbrl/07545840/sample.ixbrl`.
- Update the 3 financials tests to read from `tests/fixtures/`, not from `data/staging/`.
- Rewrite the CLI test that currently passes `"fixture-data"` so it uses a temp absolute `data_dir`; `ChBulk.__init__` resolves that path and otherwise dirties the repo root by creating `fixture-data/logs/ch-bulk.log`.
- DELETE `tests/test_staging.py::test_load_cqc_staging_large_batch_keeps_memory_bounded` — process-wide RSS measurement is too noisy to be a useful regression guard at this granularity; if the streaming loader ever regresses to materializing-all-rows, prod will catch it at 500K-row scale long before any 5K-row test will.

### Workstream B: Path helpers in `core/paths.py`

Add these helper functions:

```python
def logs_dir(data_dir: Path | str) -> Path:
    return Path(data_dir) / "logs"

def staging_root(data_dir: Path | str) -> Path:
    return Path(data_dir) / "staging"

def runs_dir(data_dir: Path | str, sync_type: str) -> Path:
    return staging_root(data_dir) / "runs" / sync_type

def run_stage_file(data_dir: Path | str, sync_type: str, batch_id: str) -> Path:
    return runs_dir(data_dir, sync_type) / f"{batch_id}.jsonl"

def raw_dir(data_dir: Path | str, source: str) -> Path:
    return staging_root(data_dir) / "raw" / source

def raw_filings_dir(data_dir: Path | str, company_number: str) -> Path:
    return raw_dir(data_dir, "companies_house") / "filings" / company_number

def derived_dir(data_dir: Path | str, domain: str) -> Path:
    return staging_root(data_dir) / "derived" / domain

def archive_dir(data_dir: Path | str, source: str) -> Path:
    return staging_root(data_dir) / "archive" / source

def validation_dir(data_dir: Path | str) -> Path:
    return staging_root(data_dir) / "validation"
```

Rewrite all ~50 call sites in tests and `ch_bulk/` to use these helpers instead of inline `Path(...) / "..."` constructions. This includes the helper functions that derive staging-file locations and batch IDs from filenames:

- `ch_bulk/db/staging.py`: `staging_path()`, `pending_staging_files()`, `batch_id_from_staging_path()`, and `StagingWriter`
- `ch_bulk/web/classifier.py`: `ClassificationChunkWriter`, `_classification_batch_id_from_path()`, and `_pending_classification_staging_files()`

After this, all staging-path knowledge lives in ONE module.

Phase 1.5 only CREATES the empty directory skeleton + updates code to write into it. Migrating useful slices from `data/old_staging/` into `archive/` is deferred to a separate optional cleanup.

Because `data/*` is gitignored, tracking `data/old_staging/README.md` requires a narrow `.gitignore` exception. That exception is part of Phase 1.5; the rest of `data/old_staging/` remains ignored.

## Public API contract

Stays stable across Phase 1.5:

- **CLI surface**: same commands, same flags, same defaults (defaults now from `core/paths.py` constants).
- **GUI**: launches via `ch-bulk ui`, same panes.
- **Top-level Python imports**: `from ch_bulk import ChBulk, SanityCheckError, SanityCheckResult, ensure_pipeline_schema` unchanged.

**One intentional behavior change**: staging file paths inside `data/staging/` move from flat (`data/staging/financials_<batch>.jsonl`) to subfolder layout (`data/staging/runs/financials/<batch>.jsonl`). Existing in-flight batches are not affected because `data/staging/` was wiped (renamed to `old_staging/`). Next pipeline run writes to new locations.

## Rationale

1. **Test isolation before next refactor.** Phase 2 plans to split `financials_enricher.py` (94KB) and `classifier.py` (66KB). Both have heavy test coverage. Without trustworthy green tests, splits fly blind.

2. **DRY path layer is overdue.** The Phase 1 `DEFAULT_DB_PATH` centralization fixed the literal-string version of this problem. Phase 1.5 finishes the job: every staging/log/raw-file path goes through one module. Future contributors stop discovering the layout by grep.

3. **Staging directory finally has semantics.** Today, every file under `data/staging/` is "stuff." After Phase 1.5: `runs/` = active mid-flight work, `raw/` = inputs we fetched, `derived/` = outputs we extracted, `archive/` = historical curated reference, `validation/` = reports. Each zone has a clear lifecycle: `runs/` rotates per batch, `raw/` accumulates and can be GC'd, `derived/` regenerates from `raw/`, `archive/` is intentional and long-lived, `validation/` is operator output.

## Risks

1. **Test path-helper signature drift.** Helpers like `run_stage_file(data_dir, sync_type, batch_id)` MUST match the layout that runtime code writes to. If a test expects `runs/financials/abc.jsonl` but code writes to `runs/financials_fetch/abc.jsonl`, tests pass but reality breaks. Mitigation: update the existing staging / classifier / financials round-trip tests so they exercise write + read via the helpers; no new tests are added in this phase.

2. **Subprocess-test cwd drift.** `test_staging.py::test_parallel_processes_complete_without_duckdb_lock_errors` spawns 2 subprocesses. They inherit cwd. If any subprocess uses CWD-relative resolution, the test will be flakier in `tests/integration/` than it was. Mitigation: subprocesses launched in tests explicitly pass an absolute `--data-dir` from the temp workspace.

3. **Memory test deletion is a one-way door.** Once deleted, no automated guard against future "load everything into memory" regressions in the loader. Mitigation: document the deletion rationale in the commit message so future contributors see why; if regression appears, write a more targeted test (e.g. mock `json.loads` to count calls).

4. **`data/old_staging/` is large** (~3.8GB in this checkout). Some tools (IDE indexers, mclone sync) may try to index it. Mitigation: confirm `data/old_staging/**` stays gitignored except for the tracked `README.md` pointer.

## What this enables (Phase 2)

After Phase 1.5 lands:
- The 3 fixture-dependent financials failures are gone and the flaky RSS-bound staging test is removed
- The remaining Playwright/browser-launch classifier errors are isolated follow-up work instead of being mixed up with fixture/path drift
- Splitting `financials_enricher.py` and `classifier.py` becomes safe — tests catch regressions
- Adding `archive/` curation step (move slices from `old_staging/`) becomes a focused cleanup commit
- Any future helper module can stop reinventing `Path(data_dir) / "..."` paths

## Locked Decisions

- `tests/fixtures/` gets a tracked `README.md`.
- `data/old_staging/README.md` is tracked via a narrow `.gitignore` exception; the rest of `data/old_staging/` stays ignored.
- `archive/` lands as an empty skeleton only in Phase 1.5. Copying historical slices from `old_staging/` into it is a follow-up.
